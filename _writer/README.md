# Writer frontend source

The public Writer still loads one stable browser asset:

```text
/assets/writer.js
```

That file is generated by `npm run build:frontend` from the ordered source fragments in this directory.

The source is intentionally split at build time rather than converted to browser ES modules in one step. The Writer has a large shared closure and substantial regression coverage; concatenating these source modules preserves its runtime semantics while making maintenance substantially easier.

Current source order:

```text
00-core.js
01-preview.js
02-state-library.js
03-publishing.js
04-editor-tools.js
05-media.js
06-bootstrap.js
```

Responsibilities:

- **core** — DOM/state setup, frontmatter, Markdown/HTML-block helpers, shared utilities.
- **preview** — Markdown rendering, preview patching, image/video hydration, direct media layout controls.
- **state-library** — article state, GitHub transport, autosave, article library loading/rendering.
- **publishing** — publish validation, conflict detection, save/publish/schedule lifecycle, live URLs.
- **editor-tools** — cursor insertion, link/embed helpers, toolbar/tool routing.
- **media** — inline image/video markup, GitHub Release video upload, image optimization/upload.
- **bootstrap** — history/export helpers, event binding, drag/drop, shortcuts, initialization.

Do not edit `assets/writer.js` directly. CI runs `npm run check:frontend` and fails if the public bundle does not match these source fragments.

A source change should normally be committed together with the regenerated `assets/writer.js`.
